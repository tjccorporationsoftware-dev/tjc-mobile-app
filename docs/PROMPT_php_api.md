> - ❌ **ห้ามเข้าไปยุ่งกับโปรเจกต์แอป** `C:\Users\Peera\Desktop\tjc-mobile-app` — ห้ามอ่าน ห้ามแก้ ห้ามสร้างไฟล์ในนั้น
> - ❌ **ห้ามเสนอหรือแนบตัวอย่างโค้ดหน้าจอ** มาในรายงาน แม้จะคิดว่าเป็นประโยชน์
>
> ทำงานอยู่ใน `C:\xampps\htdocs\tjc-api` เท่านั้น จบที่ API + เอกสาร
> คนละคนจะเป็นผู้ทำหน้าจอทีหลัง โดยใช้ JSON ที่รายงานไว้ในส่วน F เป็นสัญญา

- ระบบนี้เป็น PHP ล้วน ไม่มี framework รันบน XAMPP ใช้ **mysqli** (ไม่ใช่ PDO) เชื่อม DB ผ่าน `db_connect.php` ได้ตัวแปร `$conn`
- งานนี้คือ **เปิด API ให้แอปมือถือ (React Native) เข้าถึงโมดูลนี้ได้เต็มรูปแบบ** — แอปเป็นแค่ตัววาดหน้าจอ ตรรกะและสิทธิ์ทั้งหมดอยู่ฝั่ง PHP
- **ห้ามเขียน logic ใหม่** ให้เปิดหน้าเว็บของโมดูลนั้น แล้ว **ก๊อป SQL / เงื่อนไข / การคำนวณเดิมมาใช้ซ้ำ** ไม่งั้นตัวเลขในแอปจะไม่ตรงกับเว็บ แล้วจะหาสาเหตุไม่เจอ

**กติกาของโปรเจกต์ที่ต้องรู้** (ถ้าใช้ Claude Code จะโหลด `CLAUDE.md` ที่ root ให้เองอยู่แล้ว ไม่ต้องเปิดซ้ำ — ถ้าใช้เครื่องมืออื่นให้ยึดตามนี้)

- **ระบบสิทธิ์มี 2 ชั้น อย่าสับสน**
  - ซ่อน/แสดง **ทั้งหน้า** → `canSeeMenu('ไฟล์.php')` อิงตาราง `master_pages` คอลัมน์ **`file_name`** (⚠️ ไม่ใช่ `page_file`)
  - ซ่อน/แสดง **ปุ่มในหน้า** → `hasAction('action_code')` อิง `master_actions` + `role_actions` + `user_actions` + `user_denied_actions`
  - `role === 'admin'` ผ่านทุกอย่างในทั้ง 2 ชั้น
- **ก่อนเขียนฟังก์ชันใหม่ ให้ `grep` เช็คชื่อซ้ำก่อนเสมอ** — ไฟล์ในโปรเจกต์นี้ยาว 2,000–3,000 บรรทัด และเคยมีฟังก์ชันชื่อซ้ำทับกันเงียบ ๆ มาแล้ว
- **แก้ไฟล์เดิม = แก้เฉพาะจุดที่ตั้งใจ** ห้ามจัดรูปแบบ/เรียงลำดับใหม่ทั้งไฟล์
- ชื่อคอลัมน์จริงบางตัวต่างจากที่ไฟล์อื่น alias ไว้ (เช่นตาราง `cars` ใช้ `plate` และ `car_number` แต่ `api_fm.php` alias เป็น `plate_number` / `fleet_number`) — **ยึดชื่อจริงในตาราง**
- แสดงผลวันที่ต่อผู้ใช้เป็น **พ.ศ.** (ค.ศ. + 543) แต่ **ค่าที่ส่งใน JSON ต้องเป็น ค.ศ. รูปแบบ MySQL** ตามข้อ D.2

# ส่วน C — ขอบเขตงาน: ทำให้ครบทุกอย่างที่เว็บทำได้

**หลักการ:** ไม่ต้องเดาว่าแอปจะเอาไปแสดงอะไร — **เว็บของโมดูลนี้ทำอะไรได้ ให้ API ทำได้ทั้งหมด** ทั้งอ่าน เพิ่ม แก้ไข ลบ อัปเดตสถานะ อัปโหลดไฟล์ ค้นหา และข้อมูลประกอบทุกชนิด
ฝั่งแอปจะเป็นคนเลือกเองทีหลังว่าจะหยิบ action ไหนไปใช้

### ขั้นที่ 1 — สำรวจก่อน (ห้ามข้าม)

เปิดหน้าเว็บทุกหน้าที่ระบุใน A2 (และ `grep` หาหน้าอื่นในโมดูลเดียวกันที่เจ้าของงานอาจลืมใส่) แล้วทำรายการว่ามีความสามารถอะไรบ้าง:

- ตารางไหนบ้างที่เกี่ยวข้อง คอลัมน์อะไร ความสัมพันธ์ยังไง
- หน้านั้นแสดงอะไร — รายการ, การ์ดสรุป/สถิติ, กราฟ, รายละเอียดรายตัว, ประวัติการแก้ไข
- มีตัวกรอง / ค้นหา / แบ่งหน้า อะไรบ้าง
- มีปุ่มอะไรบ้าง — เพิ่ม / แก้ไข / ลบ / อนุมัติ / ยกเลิก / เปลี่ยนสถานะ / อัปโหลด / พิมพ์ / export
- ปุ่มไหนถูกครอบด้วย `hasAction('...')` และใช้ `action_code` อะไร (**ต้องจดไว้ให้ครบ**)
- ข้อมูลประกอบที่หน้านั้นโหลดมาใส่ dropdown (รายชื่อบริษัท ลูกค้า ประเภท สถานะ ผู้ใช้ ฯลฯ)
- **โมดูลนี้อัปโหลดไฟล์ไปโฟลเดอร์ไหน — ต้องหาเอง ห้ามเดา**
  `grep` หา `move_uploaded_file`, `$upload_dir`, `$target_dir`, `uploads/` ในหน้าเว็บของโมดูลนี้ แล้วใช้ **โฟลเดอร์เดิมเป๊ะ ๆ**
  (ในระบบมีโฟลเดอร์ย่อยใน `uploads/` อยู่ 33 อัน เช่น `delivery_proofs/`, `estimates/`, `slips/`, `lg_files/`, `service_requests/`, `excess_files/`, `contracts/` — และบางหน้าก็ทิ้งไฟล์ไว้ที่ราก `uploads/` เลยโดยตั้งชื่อขึ้นต้นเป็นรหัสโมดูลแทน เช่น `acc_`, `app_`)
  **ห้ามสร้างโฟลเดอร์ใหม่ / ห้ามเปลี่ยนที่เก็บ** ไม่งั้นไฟล์ที่อัปจากแอปจะไม่โผล่ในเว็บ และรูปเดิมของเว็บจะไม่โผล่ในแอป
  ถ้าโมดูลนี้ไม่มีการอัปโหลดไฟล์เลย ให้ระบุไว้ในรายงาน

### ขั้นที่ 2 — ทำตารางแมปก่อนเขียนโค้ด

```
ความสามารถบนเว็บ             →  action ที่จะสร้าง
ตารางรายการ + ค้นหา + กรอง   →  get_list
การ์ดสรุป / กราฟด้านบน        →  get_dashboard
กดดูรายละเอียด               →  get_detail
dropdown ทุกตัวในฟอร์ม        →  get_master_data
ปุ่มบันทึก / แก้ไข            →  save   (มี id = แก้ไข, ไม่มี id = เพิ่มใหม่)
ปุ่มลบ                       →  delete
ปุ่มเปลี่ยนสถานะ / อนุมัติ     →  update_status
อัปโหลดไฟล์แนบ               →  รวมไว้ใน save
```

**ถ้าแมปแล้วได้เกิน 15 action ให้หยุด รายงานรายการมาให้ยืนยันก่อน** แล้วค่อยเขียน

### ขั้นที่ 3 — กติกาตั้งชื่อ action

- อ่าน: `get_xxx` · เขียน/แก้: `save_xxx` · ลบ: `delete_xxx` · เปลี่ยนสถานะ: `update_xxx_status`
- ใช้ **snake_case** ตัวเล็กทั้งหมด และไม่ต้องใส่ชื่อโมดูลซ้ำถ้าชื่อไฟล์บอกอยู่แล้ว (ไฟล์ของโมดูลคลังสินค้า ใช้ `get_list` พอ ไม่ต้อง `get_warehouse_list`)
- **1 action = 1 ความสามารถ** อย่ายัดหลายอย่างไว้ใน action เดียวแล้วแยกด้วย `type=`

### ขั้นที่ 4 — ทุกโมดูลต้องมีอย่างน้อย 4 ตัวนี้

แม้เว็บจะไม่มีหน้าตรง ๆ ก็ต้องมี:

| action            | ทำอะไร                                                              |
| ----------------- | ------------------------------------------------------------------- |
| `get_list`        | รายการหลัก รองรับ `search`, ตัวกรองของโมดูลนั้น, `limit` / `offset` |
| `get_detail`      | รายละเอียด 1 รายการ พร้อมไฟล์แนบและรายการลูก (ถ้ามี)                |
| `get_master_data` | ข้อมูลใส่ dropdown ทั้งหมดของโมดูล รวมไว้ใน action เดียว            |
| `get_dashboard`   | ตัวเลขสรุป / สถิติ ตามที่หน้าเว็บโชว์                               |

# ส่วน D — กติกาบังคับ (ผิดข้อใดข้อหนึ่ง = แอปพัง)

## D.1 โครงไฟล์ (ไฟล์ใหม่ในโฟลเดอร์ย่อย)

สร้างโฟลเดอร์ตาม A4 แล้ววางไฟล์ตาม A3 ไว้ข้างใน หัวไฟล์ต้องเป็นแบบนี้:

```php
<?php
header("Access-Control-Allow-Origin: *");
header("Content-Type: application/json; charset=UTF-8");
header("Access-Control-Allow-Methods: POST, GET, OPTIONS");
header("Access-Control-Allow-Headers: Content-Type, Authorization, X-Requested-With");
ini_set('display_errors', 0);
error_reporting(E_ALL);
ob_start();

require_once __DIR__ . '/../db_connect.php';          // ⚠️ ต้องเป็น __DIR__ เพราะอยู่ในโฟลเดอร์ย่อย
require_once __DIR__ . '/../mobile_permissions.php';
date_default_timezone_set('Asia/Bangkok');

$action  = $_REQUEST['action'] ?? '';                  // รับได้ทั้ง GET และ POST
$user_id = intval($_REQUEST['user_id'] ?? 0);

function out($data) {                                  // ใช้ตัวนี้ตอบทุกครั้ง
    if (ob_get_length()) ob_clean();                   // ทิ้ง output ขยะที่อาจรั่วมา
    echo json_encode($data, JSON_UNESCAPED_UNICODE);
    exit();
}
function ok($data = [])            { out(["status" => "success"] + $data); }
function fail($msg, $code = '')    { out(["status" => "error", "message" => $msg, "code" => $code]); }

try {
    if ($action === 'get_list') {
        // ...
        ok(["list" => $rows]);
    }

    // ... action อื่น ๆ ...

    fail("ไม่รู้จัก action: {$action}");                // ⚠️ ต้องมี ไม่งั้นพิมพ์ผิดแล้วได้หน้าขาวเงียบ ๆ
} catch (Exception $e) {
    fail("server_error: " . $e->getMessage());
}
```

**⚠️ ผลจากการอยู่ในโฟลเดอร์ย่อย — พลาดตรงนี้บ่อยที่สุด**

1. `require` ทุกตัวต้องใช้ `__DIR__ . '/../ชื่อไฟล์.php'` ไม่ใช่ `'ชื่อไฟล์.php'` เฉย ๆ
2. พาธอัปโหลดต้องเป็น `__DIR__ . '/../uploads/xxx/'` ไม่ใช่ `'uploads/xxx/'` (ไม่งั้นไฟล์ไปตกในโฟลเดอร์ย่อย แล้วเว็บมองไม่เห็นรูปที่แอปอัปโหลด)
3. ใน DB ยังคง **เก็บแค่ชื่อไฟล์** เหมือนเดิม ห้ามเก็บพาธที่มีชื่อโฟลเดอร์ใหม่ปนเข้าไป
4. URL ที่แอปเรียกจะกลายเป็น `.../tjc-api/【A4】/【A3】?action=...` — ต้องระบุไว้ในรายงานส่วน F

## D.2 กติกา JSON

1. **คืน JSON เท่านั้น** ห้ามมี output อื่นหลุดก่อน JSON (ไม่มี `echo` ทดสอบ, `print_r`, `var_dump`, HTML, บรรทัดว่างหน้า `<?php`, ไม่มี BOM)
2. **`JSON_UNESCAPED_UNICODE` ทุกครั้ง** — ไม่ใส่แล้วภาษาไทยกลายเป็น `\u0e01` (ฟังก์ชัน `out()` จัดการให้แล้ว ให้ตอบผ่าน `ok()` / `fail()` เสมอ ห้าม `echo json_encode` เอง)
3. **รูปแบบ response คงที่**
   - สำเร็จ: `{"status":"success", ...ข้อมูล}`
   - ล้มเหลว: `{"status":"error","message":"ข้อความภาษาไทย"}`
   - ไม่มีสิทธิ์: `{"status":"error","code":"no_permission","message":"..."}`
4. **วันที่ส่งเป็น string MySQL** `YYYY-MM-DD` หรือ `YYYY-MM-DD HH:MM:SS` (แอปแปลง พ.ศ. เอง)
   จะแปลงไทยให้ด้วยก็ได้ แต่ให้เพิ่มเป็น**คีย์ใหม่** เช่น `doc_date_thai` ห้ามทับคีย์เดิม
5. **ไฟล์แนบ/รูป คืนแค่ชื่อไฟล์** (`"abc.jpg"`) ไม่ต้องคืน URL เต็ม — แอปเติม path เอง
   หลายรูปในคอลัมน์เดียว คั่นด้วย `,` ตามแบบเดิมของระบบ
6. **ทุก action ที่คืนเป็นรายการต้องมี `LIMIT`** (ค่าเริ่มต้น 200) และรองรับ `limit` / `offset` จากพารามิเตอร์
7. ตัวเลขที่เอาไปคำนวณต่อ ให้ `intval()` / `floatval()` ก่อนใส่ลง JSON อย่าปล่อยเป็น string

## D.3 กติกาความปลอดภัยและสิทธิ์

1. **ห้าม `require_once 'auth.php'` และห้ามพึ่ง `$_SESSION` เด็ดขาด**
   API มือถือไม่มี session และ `auth.php` จะ `header("Location: login.php")` ทำให้แอปได้ HTML ของหน้าล็อกอินแทน JSON แล้วพังทันที
   → รับ `user_id` เป็นพารามิเตอร์แทน และ **ทุก action ต้องรับ `user_id`**
2. **prepared statement (`prepare` + `bind_param`) ทุก query ที่มีค่าจากผู้ใช้**
   ⚠️ โค้ดเดิมหลายจุดยังต่อสตริงลง SQL ตรง ๆ อยู่ (`api_mobile.php` หลายก้อนใช้ `real_escape_string`, `api_fm.php:1448`, `fm_print.php:49`) — **ห้ามลอกแพตเทิร์นนั้นมา**
3. **ทุก action ที่ เพิ่ม / แก้ไข / ลบ / เปลี่ยนสถานะ ต้องเช็คสิทธิ์เสมอ**
   ใช้ `action_code` **ตัวเดียวกับที่หน้าเว็บใช้ใน `hasAction()`** (ที่จดไว้ตอนสำรวจ):
   ```php
   if (!hasActionForUser($conn, $user_id, 'edit_warehouse')) {
       fail("ไม่มีสิทธิ์ทำรายการนี้", "no_permission");
   }
   ```
   ⚠️ `hasActionForUser()` รับ **`$conn` เป็นพารามิเตอร์ตัวแรก**
4. **action ที่อ่านข้อมูล ให้ส่งผลสิทธิ์กลับไปด้วยทุกครั้ง** เพื่อให้แอปซ่อน/โชว์ปุ่มได้:
   ```php
   ok([
       "list"       => $rows,
       "can_edit"   => hasActionForUser($conn, $user_id, 'edit_warehouse'),
       "can_delete" => hasActionForUser($conn, $user_id, 'delete_warehouse'),
   ]);
   ```
   ห้ามเอาสิทธิ์ไปฝังตอน login เพราะแอปเก็บค่า login ลงเครื่องครั้งเดียว แก้สิทธิ์แล้วจะไม่เห็นผลจนกว่าจะ logout
5. **ลบข้อมูลให้ทำตามแบบที่เว็บทำ** — ถ้าเว็บใช้ soft delete (ตั้ง flag) ห้ามเปลี่ยนเป็น `DELETE` จริง และกลับกัน
6. **บันทึกคนทำรายการตามแบบที่เว็บทำ** — เว็บใช้ `$_SESSION['fullname']` ส่วน API ต้องหาจาก `user_id` ที่ส่งมา ไม่ใช่รับชื่อจากแอปตรง ๆ
